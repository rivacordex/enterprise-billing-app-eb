  - **Design decision — `metadata.reversalLegs` stored at creation time, not re-derived at posting time:** the generic `approveDocument → postDocument` flow must be usable for four-eyes reversals (any doc with `auto_post_limit = 0`) without a second transfer-lookup round-trip inside the approval callback. Storing pre-computed opposite legs as `{fromAccountId, toAccountId, amount}[]` in `document.metadata.reversalLegs` at `reverseDocument`/`reverseLine` creation time lets `postDocument` detect `doc.reversalOf != null` and pass them straight to `finalizePosting` — the entire approval flow is unchanged. A sanity check (`stored.length === lines.length` + amount equality) guards against metadata corruption.
  - **Design decision — `reversedByLineId` stamped before `submitDocument`, not after:** stamping inside the same creation transaction (before the reversal doc transitions out of `draft`) serves as a durable lock against double-reversal. Even if the reversal doc ends up in `pending_approval`, the original lines already carry `reversedByLineId` and will be rejected by both `reverseDocument` and `reverseLine` on any re-attempt. Matches `refundPayment`'s allocation-line stamping precedent exactly.
  - **Design decision — line-level reversal only flips original state to `reversed` when ALL lines are covered:** `reverseLine` checks every line on the original document (not just the selected ones) against `l.reversedByLineId !== null || selectedSet.has(l.documentLineId)`. A partial line-level reversal leaves the original in `posted` so it remains eligible for further reversals. Full coverage (all lines either previously stamped or stamped now) triggers `compareAndUpdateState → reversed`.
  - **`ReversalPreview.lastModified` is `string` (ISO), not `Date`:** `Date` objects don't survive Next.js server-action JSON serialization boundary — they arrive as strings on the client. The action returns the ISO string, the panel passes it to `reverseDocumentAction` as-is, and `z.coerce.date()` in the schema converts it back to `Date` for the service layer. Avoids a subtle runtime bug where `input.lastModified.getTime()` would fail silently.
