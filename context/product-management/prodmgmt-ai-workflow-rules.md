## 1. Operating Approach

Apply general §1 in full, plus these.

1. **Read the companion docs before writing a line, and verify the tree before trusting any status line** (§0). Do not infer the current shape from code alone or from docs alone.
2. **Cite the authorizing decision before coding.** Name the plan section (§2.2–§2.7, §3, §4), the open question it closes (Q1–Q4), the Module Invariant (#61–#73 or an amended one), the code-standards **(normalize)** rule, or the Part 6 unit that mandates what you are about to build. No citation, no mandate — stop and ask.
3. **Build in the order of §0.2, one unit per pass.** Do not reorder, do not overlap, and do not start a unit whose predecessor is not committed and reviewed.
4. **Treat the repository as the whole blast radius above the database.** If a unit finds itself editing a component, an action, a service's signature, a Zod branch (beyond pm69's caps), an audit payload builder or a search-param schema, it has left this update. Stop and re-scope (code-standards §1.48).
5. **Decompose on write, reassemble on read, in one file.** `toEnvelope` and `fromEnvelope` exist only in `db/repositories/product-offering-price.ts` (Inv. #61). Write no second assembly point — not in a seed, not in a fixture, not in a test helper, not in a flow.
6. **Make the smallest correct change.** No refactor, rename, folder reorg or dependency change rides along. This update adds **no** dependency and touches **no** root config.
7. **State the unit's scope, files, permission and tests before editing**, and stop and re-scope the moment you touch a file that is not on that list.

## 3. Scoping — No Speculative Changes

Apply general §2 in full, plus these. The numbering is fixed; other docs will cite §3.1, §3.5 and §3.9 directly.

2. **Do not add a column, a table, a status, a flag or a counter the current unit does not need.** Not a `step_no`, not a `currency` on a subtype table, not a `unit_of_measure` copy, not a `sequence`, not a `pla_spec_id` on `pop_usage_rate`, not a `display_order` on prices. Eleven tables and one view is the ceiling (code-standards §6.35).
3. **Do not add a fifth reference row or a sixth pair.** `price_component_type` holds four rows and `price_component_price_type` five, exactly as plan §2.3 seeds them. `negotiated_override` is **not** a row (Inv. #39).
4. **Do not make the reference tables editable.** No UI, no action, no service, no seed script, no admin page. A new type is a migration and a design review (Inv. #64).
5. **Do not declare the view in Drizzle, and do not read it from the app.** The repository reads the tables through `relations()`; the engine reads the view by grant (Inv. #67).
6. **Do not round-trip through the envelope in production code where a row copy will do.** `branchOfferingAsDraft` copies rows with an id map (code-standards §1.60); the **test** proves envelope equality.
7. **Do not write a standalone backfill script, a data-fix script, a dual-read shim or a compatibility view.** The backfill is inside `0056` and verifies itself; the only legal "compatibility" is the repository reassembling the envelope (code-standards §1.30 amended).
8. **Do not change what the flows and `rp.py` compute.** The rewrite is mechanical — column for JSON path, `price_type` for the `CASE` term in the `lead()` partition (code-standards §1.56). A diff that touches proration, rounding, the BAN grain, the three-factor subscriber identity or `CARD_DRIVEN_RATING_UNSUPPORTED` has left scope.
9. **Do not add a typed result code for a database refusal.** The composite FK, the pair FK, the step PK and the deferred trigger fire only when Zod was bypassed; throw (code-standards §1.51). Keep `isUniqueViolation(err, "product_offering_price_lane_start_unique")` working by keeping the index name.
10. **Do not fan out per row.** The detail load is one relational query (code-standards §1.61); the backfill is set-based SQL; the branch copy is one insert per table with the id map. No `Promise.all` over headers, no per-step query.
11. **Do not touch `reject_summary`.** It stays jsonb, Zod-typed and bounded, exactly as pm58 left it. Platform §3's JSONB rule still binds it.
12. **Do not disable, weaken or delete a guardrail to make a unit pass.** Re-baseline 13; re-scope 2, 16, 27, 32, 41 as this update requires; land 42–50; every other guardrail passes as written.
