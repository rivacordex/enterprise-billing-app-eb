## Recurring patterns (apply across units)

- **Permission-name ripple:** a new `PERMISSION_NAMES` key must be added to every `EffectivePermissionMap` literal fixture (~25+ test files; `tsc` catches literals, not array-length assertions). See `[[permission-name-addition-ripple]]`.
- **Cross-schema integration-test ripple:** a new pgSchema needs `DROP SCHEMA IF EXISTS "<schema>" CASCADE` in every existing integration test's reset. See `[[new-pgschema-integration-test-ripple]]`.
- **Audit event-type ripple:** each new `AUDIT_EVENT_TYPES` entry needs an `AUDIT_EVENT_CATEGORY_MAP` entry (`tsc`-caught) and a bumped count in `tests/components/audit-log-filters.test.tsx` (not caught). See `[[audit-event-type-addition-ripple]]`.
- **Repository mutation allow-lists:** `*-repository-exports` / `*-module-boundaries` guardrails get an allow-list entry in the same commit as each write.
- **New-route ripple:** add every new page's URL to `ROUTE_MANIFEST` in `tests/app/route-manifest.test.ts`.
- **Seam discipline:** shell units leave `{/* pmXX */}` seams; each follow-up fills exactly one.
- **`db → validation` ESLint boundary:** `db/**` or `types/**` files embedding a Zod shape need `"validation"` in their allowed imports in `eslint.config.mjs`.
- **Verification posture:** repo-wide `tsc --noEmit` + `eslint .` + `prettier --check .`, the full unit suite, `next build`, and live-DB integration/concurrency tests on disposable Postgres 16 containers (never the dev stack's `DATABASE_URL` — `[[local-docker-dev-stack]]`). CI SAST/DAST and browser walkthroughs are outside this tooling.

## Permanent lessons (do not re-learn)

- **Grant-per-schema on deploy:** any new schema adds its own grant/revoke block (incl. sequences) to `bootstrap-db-roles.sql` in the same change as its migration, and the file is re-run (pm09 `42501` outage). Engine-role files (`rating-db-roles.sql`, `billrun-db-roles.sql`) enumerate `product` tables one by one — a new table needs an explicit grant there too. See `[[db-role-bootstrap-per-schema]]`.
- **TOCTOU-safe status reads:** status-gated decisions read the target on `tx` with `FOR UPDATE` immediately before the write — a pre-transaction read is review-blocking (fixed in pm14, pm15, pm16, pm20).
- **Concurrency is proven, not assumed:** races are verified by live-DB tests looped 4×; "latest" history ordering uses the sequence id, not `created_at`; concurrent same-family branches serialize on `pg_advisory_xact_lock(hashtext(rootId))`.
- **DRAFT-guard fixtures:** insert an offering as DRAFT, seed children, then flip to ACTIVE. See `[[pm36-draft-guard-trigger-fixture-ripple]]`.
- `PRODUCT_ORDER_FAILED` is seeded-but-unused by design (pm28 full-rollback deviation), not open work.
