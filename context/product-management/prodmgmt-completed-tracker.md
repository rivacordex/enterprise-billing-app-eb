**Verification posture (every unit):** `tsc --noEmit` + `eslint .` +
`prettier --check .` clean repo-wide, the full unit suite, and `next build`;
write / versioning / lifecycle behavior is covered by live-DB integration +

(never the dev stack's own `DATABASE_URL` — see `[[local-docker-dev-stack]]`).
CI SAST/DAST and a live dev-server browser walkthrough remain outside this
tooling's reach (same caveat across all three ship gates).

## Recurring patterns (apply across units — not repeated per-unit below)

- **Permission-name ripple:** adding a name to `PERMISSION_NAMES` forces that
  key into every hardcoded `EffectivePermissionMap` object-literal fixture
  across ~25+ test files (`tsc`-caught for object literals, but a few hardcoded
  array-length assertions are not). See `[[permission-name-addition-ripple]]`.
- **Cross-schema integration-test ripple:** every pre-existing
  `tests/**/*.integration.test.ts` doing a fresh `DROP SCHEMA … CASCADE` +
  migrate cycle needs a `DROP SCHEMA IF EXISTS "<newschema>" CASCADE` added
  first — otherwise the next file's migration fails with "schema already
  exists." See `[[new-pgschema-integration-test-ripple]]`.
- **Audit event-type ripple (every write unit):** each new `AUDIT_EVENT_TYPES`
  entry needs (1) an `AUDIT_EVENT_CATEGORY_MAP` entry in `types/audit-log.ts`
  (`tsc`-caught) and (2) a bumped event-type count + optgroup assertion in
  `tests/components/audit-log-filters.test.tsx` (**not** `tsc`-caught). See
  `[[audit-event-type-addition-ripple]]`.
- **Repository mutation allow-lists:** the `*-repository-exports` and
  `*-module-boundaries` guardrails carry a per-write-unit allow-list entry —
  expected, not a surprise; add the entry in the same commit as the write.
- **New-route ripple:** `tests/app/route-manifest.test.ts`'s `ROUTE_MANIFEST`
  is a strict set-equality check against every real `app/**/page.tsx` — a new
  page 404-fails that test until its literal URL is added to the array.
- **Region/seam discipline:** a shell unit builds placeholder frames with
  `{/* pmXX */}` seam comments; each follow-up unit fills exactly one seam,
  leaving the others byte-unchanged (pm05→pm08, pm18→pm23, pm27→pm29/pm31/pm33).

## Permanent lessons (from post-ship fixes — do not re-learn)

- **Grant-per-schema on deploy:** a deployed instance 500'd (`42501: permission
  denied for schema product`) because `bootstrap-db-roles.sql` only granted on
  `core`. **Any new schema must add its own grant/revoke block (incl. sequence
  grants) in the same change that adds its migration, and the file must be
  re-run**, or this recurs. See `[[db-role-bootstrap-per-schema]]`.
- **TOCTOU-safe status reads:** a status-gated branch/lifecycle decision must
  read its target's status on the transaction (`tx`, `FOR UPDATE`),
  immediately before the write — never from a pre-transaction `db` snapshot.
  This exact bug was found and fixed independently in pm14, pm15, pm16, and
  pm20; treat a pre-transaction status read as a review-blocking defect on
  sight (code-standards §1 rule 13).
- **Concurrency is proven, not assumed:** single-active-per-family (pm16),
  approve-vs-approve / approve-vs-reject (pm30), and suspend-vs-terminate
  (pm32) are each verified by live-DB races looped 4×. `inventory_status_history`
  "latest" ordering is by the sequence id, not `created_at` (which is fixed at
  transaction start and can invert under lock contention — pm32 fix).
