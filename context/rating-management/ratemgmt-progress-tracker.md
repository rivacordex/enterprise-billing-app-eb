## Open Questions

- **rm13** — (1) "A rating migration" is identified by filename (`/rating/i`), not by parsing the target schema — misses a hypothetically differently-named future one. (2) The scanner can't catch an unqualified `SET search_path = billing` write; the rm03 grant suite is the real runtime guarantee (rm13 D4 is the source-level half only).
- **rm12** — (1) `completeness_check.py` clears only its own two codes (five RL-raised auto-clearing codes still lack a `CLEARED` emitter). (2) KV config is a delimiter scalar — fine now, but a limitation if a future unit needs richer per-`udr_type` config. (3) **Cross-midnight attribution (open):** a batch is attributed to a period by `received_at`'s UTC calendar day, so a delivery late across UTC midnight false-raises `FILE_NOT_RECEIVED` for the prior day (never cleared) and never `FILE_LATE` — needs a period/window-model decision (alarm semantics, §5.1). (4) **Idempotency vs the async sweep (open):** raise/clear guards read `process_log`, populated only by the 5-min `log_sweep`; a >1h sweep lag can double-raise/clear.
- **rm11** — (1) PRP's `DUPLICATE_BATCH` dedup matches `(file_key, checksum)` regardless of status, so a byte-identical resend after a strand resolves is still discarded rather than reprocessed (rm11 only guarantees a *corrected* reissue claims cleanly; revisit rm07's dedup). (2) The "on flow start" trigger has no confirmed Kestra OSS primitive — uses a `Schedule` `backfill` catch-up, unconfirmed vs v1.3.35; the 5-min cadence bounds the worst case.
- **rm10** — (1) `rl.py`'s rm10 changes only ran via review + the 2026-09-06 static half — run the DB-gated suite before fully trusting. (2) Cross-period detection correlates by `udr_key` alone (detects the crossing, not the exact predecessor→successor pairing). (3) `SHRINKING_REISSUE` compares `parsed_count` run-N vs N-1, not a live-row count (can't tell "fewer records" from "same total, fewer distinct keys").
- **rm09** — (1) `LOOKUP_MISS` folds into `discarded_count`. (2) Terminal status is `PARTIAL` on *any* shortfall, not only PRP rejects.
